# Изменения кода и физических данных

## Рабочая среда

Используйте отдельное виртуальное окружение и зависимости из `requirements.txt`. Входная точка — `run.py`; каталог `src` добавляется им в `sys.path`. Сборка не требует установки проекта как Python-пакета.

Перед изменением воспроизведите ошибку на небольшом JSON. Не прикладывайте весь результат большого расчёта вместо минимального примера. Для ошибки окна нужны версия, выбранный файл, действия, журнал и ожидаемое поведение.

## Изменения физики

Коэффициенты, уровни и сечения находятся в `data`, алгоритмы — в `src`. Новые данные сопровождайте DOI/URL, исходными единицами, диапазоном, способом преобразования, контрольной суммой и оценочным статусом. Не восстанавливайте произвольную σ(E) из единственного Maxwellian k(T) или Υ(T). Альтернативные измерения одного канала выбирают как альтернативы, а не складывают.

Новое физическое приближение необходимо явно описать в `docs/PHYSICS_RU.md`, показать его выключатель и границы применимости. Не исправляйте численный баланс скрытым добавлением частиц, перенормировкой решения или подгонкой температуры. Для нового канала проверяйте ядра каждого элемента, заряд, продукты и энергию Q.

## Проверки перед PR

```bash
python run.py test
python run.py --config configs/study_01_decay.json --check
python run.py --config configs/study_01_decay.json
python tools/check_first_test.py
python tools/build_reference.py --check
python tools/check_repository.py
```

Для изменения конкретного процесса добавьте независимый предельный или аналитический тест. Для чистой правки текста новый тест не требуется. Графические тесты с Tk нуждаются в дисплее; CI Linux запускает их через Xvfb. Пропуск теста не считать прохождением.

После изменения строк кода обновите карту: `python tools/build_reference.py`. После изменения параметров задания — `python tools/make_student_tests.py`. Опишите в PR конкретную ошибку, результат исправления, выполненные проверки и оставшиеся ограничения. Авторов и научные ссылки сохраняйте.

## Структура изменений

Не меняйте названия ID существующих уровней и реакций без миграции сохранённых результатов. Не включайте `outputs`, кэши, `.venv`, журналы запуска и временные выгрузки в коммит. Обновляйте `VERSION.txt` и `CHANGELOG.md`; все текущие метаданные версии читают `VERSION.txt`.
