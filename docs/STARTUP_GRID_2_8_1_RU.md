# Исправление запуска с газом 300 000 K · 2.8.1

## Причина остановки

В присланном `launcher.log` расчёт останавливался до интегрирования с сообщением «Ионная сетка не покрывает дрейф и тепловой хвост». В присланном `gas_probe.json` температура тяжёлых частиц — **300 000 K**, тогда как верхняя граница их энергетической сетки — **50 эВ**.

Для этой температуры kT = **25.852 эВ**. Уже существующая проверка инициализатора требует Emax ≥ 8kT = **206.816 эВ** при нулевой средней скорости. Поэтому ошибка относится и к нейтральным H/He, а не обязательно к ионам. Она вызвана недостаточной границей сетки, не внешним дрейфом.

## Что исправлено

- Для тяжёлых частиц добавлен Emax=`auto`, как и для электронов. Учитываются температуры, массы, скорости и составные пучки начального газа, включённые источники, резервуарные границы и диапазоны файлов распределений. Для тепловых входов используется прежний критерий покрытия с запасом 10%; обычная нижняя граница автоматического Emax — прежние 50 эВ. Фазовые файлы за пределы их диапазона не продолжаются.
- При ручной слишком маленькой границе сообщение называет фактические Emax, Ti, kTi, требуемый минимум и поле интерфейса для исправления. Температура не уменьшается автоматически.
- В журнале этап энергетических сеток теперь отделён от подготовки атомных данных.
- Исправлена оценка оставшегося времени. Повторное обновление на границе сохраняемого момента могло отличаться от предыдущего лишь на один разряд float; деление на такую долю порождало миллионы часов ETA. Незначительные обновления теперь накапливаются для оценки времени; сам шаг физического расчёта не меняется.

## Как запустить ваши параметры

В этой сборке в окне запуска выберите **configs/gas_probe_user_fixed.json**. Это ваш присланный файл с **единственным изменением**: `heavy_phase_grid.energy_max_eV` заменено с 50 на `auto`. Температуры, состав, концентрации, 10 ячеек, слой 1 см, оба внутренних источника, свет на границе и времена импульсов сохранены. Обычный пример `gas_probe.json` тоже оставлен в списке.

В консоли:

```bash
python run.py --config configs/gas_probe_user_fixed.json
```

Если пока используете версию 2.8, её можно запустить с вашим старым файлом, вручную заменив **50 на 300** в `heavy_phase_grid.energy_max_eV`. Это лишь расширение сетки, не изменение температуры.

В новом редакторе: **EEDF / ионы → Сетки кинетической энергии → Тяжёлые частицы · Emax / auto**. При дальнейших изменениях температуры оставьте `auto` либо задайте подходящую численную границу. Подбор Emax обеспечивает покрытие входов; сходимость по числу энергетических узлов проверяется отдельно.

## Результат проверки вашего случая

Прежняя ошибка воспроизведена в 2.8. В 2.8.1 автоматический Emax получился **227.497598 эВ**. Полный расчёт выполнен до **2×10⁻⁷ с**, **100 принятых шагов**, без изменения физических параметров. Проверки массы, заряда, энергии, кинетики и фотонных событий пройдены. В финальном журнале максимальная показанная ETA — около 24.5 с, а не миллионы часов.

Банк физических данных по-прежнему конечен; код возврата 2 в этом случае связан с ограничениями данных. Тепловые коэффициенты не экстраполировались на 300 000 K. Сечения, формулы скоростей и опубликованные интервалы не менялись.

## Почему из Te=30 эВ ещё не следует наличие электронов

В вашем начальном составе есть только нейтральные H и He, а `electron_initial.density_cm3` отсутствует. В режиме «по заряду ионов» это означает **начальное nₑ=0** во всех десяти ячейках. Te=30 эВ задаёт форму распределения для имеющихся электронов и не создаёт частицы.

Если эксперимент предполагает начальные электроны, на вкладке **Расчёт** снимите «Исходная концентрация электронов — по заряду ионов» и задайте nₑ. Можно также задать исходные ионы в составе или независимый электронный источник. В исправленном файле электроны автоматически не добавлялись.

| `src/phase_grid_setup.py` | Определение общей энергетической границы тяжёлых частиц по входам |

| `src/progress.py` | Устойчивость ETA к почти совпадающим обновлениям |
| `tests/tests_heavy_auto_grid.py` | Горячий газ, источники, массы, файлы, резервуары, ручные границы, ETA и сохранение параметров в Tk |
