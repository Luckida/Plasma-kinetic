# Добавление элементов и данных из сети

## Сначала — выбрать задачу

Добавление записи в `atomic_data.species` запускает только те импортёры, которые действительно подключены. Неизвестный элемент с отсутствующим дескриптором не получает таблицы гелия. Окно **«Элементы и данные»** и команда `python run.py data ...` выполняют одну и ту же подготовку.

Различайте три операции:

1. **Добавить уже подключённый элемент в смесь.** Для H, He, Li, Na укажите имя/стадию, начальные концентрации и распределения. Подготовьте данные, затем запустите смесь.
2. **Подключить новый атомный источник.** Нужны реальные уровни, массы, общая шкала ионных стадий, A и электронные/фото-данные. Дескриптор определяет импортёр и источники; он не достраивает отсутствующую физику.
3. **Добавить реакции между компонентами.** Это отдельная работа со стехиометрией, k(T)/σ(E), энергиями продуктов и применимостью. Новый атомный источник автоматически не создаёт He*–X или X–Y реакции.

## Подключённые элементы

В параметрах, лежащих в `configs/`, пути относительны **файлу параметров**:

```json
"atomic_data": {
  "species": ["H", "He", "Li", "Li II", "Na"],
  "element_directory": "../data/elements",
  "prepared_directory": "../data/elements",
  "cache_directory": "../cache/atomic_sources",
  "nmax": 9,
  "offline": false
}
```

Добавьте соответствующие `initial_cm3` и `heavy_initial`. Пример: `"Na": 1e8`, `"Na+": 1e6`, `"heavy_initial": {"Na": {"Ti_K":650,"uz_cm_s":0}}`. Ион и нейтрал могут иметь отдельные параметры по спектроскопическому имени `"Na II"` / `"Na I"`, которое указано в загруженных состояниях.

Подготовка без интегрирования:

```bash
python run.py data prepare --config configs/mixture_H_He_Na.json
python run.py data validate --config configs/mixture_H_He_Na.json
```

Файл `data/elements/Na/Na_0_n9/levels.csv` и соседние таблицы появляются после подготовки. `offline=true` запрещает сетевое получение недостающего источника. Сохраняйте ранее подготовленные таблицы вместе с manifest, если нужен перенос расчёта на компьютер без интернета.

## Дескриптор одного элемента

`data/elements/<символ>/atom.json` содержит только данные этого элемента:

| Поле | Смысл |
|---|---|
| `schema="ElementData-1"`, `element` | Формат и химический символ |
| `ground_stages` | Последовательные стадии от нейтрала до голого ядра: `charge`, `g`, конфигурация, квантовые числа и `ionization_eV` для каждой небезэлектронной стадии |
| `sources` | Именованные HTTPS-источники, SHA256, формат и библиографическая ссылка |
| `species` | Для каждой импортируемой стадии `<символ>_<заряд>`: масса и выбранный импортёр |
| `notes` | Научные ограничения и определения агрегированных состояний |

Пример реального дескриптора — `data/elements/Na/atom.json`. Его `adf04` указывает на источник формата `adf04_ls3`; электронный провайдер `ccc_alkali_form` проверен для нейтральных Li/Na. Нельзя использовать этот адаптер для C/O только потому, что такие названия есть на странице CCC: часть опубликованных там данных относится к **позитронам**, а не электронам.

Для любого элемента имеется второй вход: `native_csv`. Он полезен для источников с другим исходным форматом после явного преобразования в канонические таблицы. Запись стадии имеет вид:

```json
"X_0": {
  "mass_u": 0,
  "ionization_eV": 0,
  "native_csv": {
    "levels": "source_levels",
    "lines": "source_lines",
    "electron_cross_sections": "source_sigma",
    "maxwellian_upsilon": "source_upsilon"
  }
}
```

**Это схема, не рабочие физические числа:** X, масса, порог и источники должны быть заменены реальными данными. Обязательна таблица уровней. Отсутствие других таблиц даёт неполное покрытие, а не нулевые физические скорости. В `sources` каждый ключ связывается с HTTPS URL и точной контрольной суммой. Для нового дескриптора SHA256 обязателен.

Установка дескриптора сначала загружает и проверяет его таблицы во временном наборе, затем сохраняет `atom.json`:

```bash
python run.py data register --descriptor my_atom.json --element-directory data/elements
```

Существующий дескриптор не перезаписывается без явного `--replace`. Импортёр не выполняет скачанный Python/JavaScript. Если источник поменялся, неподтверждённая версия с другой контрольной суммой не подставляется.

## Канонические атомные CSV

Общие правила: UTF-8, разделитель `;`, десятичная точка; поля названы вместе с единицами. Отдельный файл на отдельный вид данных в каждой стадии.

| Файл | Основные столбцы |
|---|---|
| `levels.csv` | `id;species;configuration;n;multiplicity;L;g;energy_cm1;energy_reference;mass_u;source_index;label;source` |
| `lines.csv` | `id;lower;upper;A_s;wavelength_nm;wavelength_medium;source` |
| `electron_cross_sections.csv` | `id;kind;initial;final;energy_eV;sigma_cm2;source` |
| `maxwellian_upsilon.csv` | `id;kind;initial;final;T_K;value;units;source` |

`energy_reference` должен быть `ground_of_this_ion`; основной уровень имеет E=0. Все уровни одной стадии используют одну массу. `species` — спектроскопическое имя, например `Na I`. Значения `kind` сечения: `electron_excitation`, `electron_deexcitation`, `electron_ionization`, `electron_elastic`, `electron_momentum_transfer`. Последние два процесса различны. При ионизации `final` означает родительскую стадию, которая связывается при сборке общей шкалы.

Υ(T) имеет единицы `dimensionless_Maxwellian_effective_collision_strength`; оно не является ни скоростью реакции, ни энергетическим сечением. Для произвольной EEDF нужно именно σ(E). Научное соответствие конкретного терма исходной таблице должен установить автор импортируемого набора: совпадение буквенного названия само по себе недостаточно.

Проверяются состав/заряд, ссылки на уровни, положительность, конечность, монотонность энергетической сетки и массы. Проверка формата не устанавливает точность расчёта сечения.

## Импорт сечений LXCat/BOLSIG

Вход — распространённый текстовый экспорт с блоками `ELASTIC`, `EXCITATION`, `IONIZATION` и числовыми таблицами между пунктирными разделителями. Для другого формата программа сообщает ошибку; универсальное распознавание всех файлов LXCat не заявлено.

Скопируйте `templates/lxcat_mapping.json`, укажите:

- `projectile="electron"`;
- номер каждого блока и его реальные `initial`/`final` ID;
- физический `kind` канала;
- коэффициенты перевода исходных единиц в eV и см².

Для м² → см² коэффициент равен 10000. Если источник уже в см², нужен 1, а не 10000.

```bash
python run.py data lxcat --file exported.txt --mapping my_mapping.json --out electron_cross_sections.csv
```

Также поддержаны `--url` и обязательный для такого сетевого импорта `--sha256`. Результат содержит только сопоставленные σ(E), а соседний файл происхождения перечисляет несопоставленные блоки. Присоедините CSV к подготовленной стадии в режиме `atomic_data.local_tables=true` либо включите его как канонический источник дескриптора. Для local_tables сначала подготовьте весь банк; автоматическая повторная подготовка изменённые таблицы не перезаписывает.

## Сеть UMIST и остальные опубликованные источники

```bash
python run.py data network --elements H He Li Na --out cache/network_candidates/run1
```

По умолчанию загружается текущий `rate22_final.rates` с официального сайта. Можно указать `--file`, `--url`, `--sha256`. Сохраняются исходные номера реакций, **все** температурные интервалы, метод, оценка точности и библиография. Реакции фильтруются по участвующим элементам и разнесены по группам. k(T) записывается отдельно от `reactions.json`; пустой файл σ(E) не выдаётся за полученные сечения.

Результат имеет `reviewed=false` и остаётся набором кандидатов. Это не запрос разрешения программы: флаг отделяет загруженные, ещё не сопоставленные данные от выбранного механизма. Чтобы подключить кандидат, нужно проверить его компоненты/энергии/вид коэффициента, исключить дубли уже работающих атомных процессов и затем включить проверенную запись в рабочую папку. Суммировать два литературных коэффициента одного и того же процесса как две реакции нельзя.

Фотореакции, космические лучи, радиативная ассоциация/RR и неподдержанные законы уходят в `unsupported.csv`. Их коэффициенты нельзя употреблять как обычное бинарное k n_A n_B. KIDA, IAEA, статьи и приложения к ним можно включать через канонические таблицы и рабочие реакционные файлы; специальных универсальных парсеров всех этих источников в 2.1 нет. Указатель источников — `data/source_guide.json`.

## Добавление межкомпонентной реакции

В папке выбранной группы, например `data/reactions/H--He/`, используются:

1. `reactions.json`: ID, два реагента, два/три продукта, тип, ссылка на коэффициент/сечение, источник, соглашение о числе событий; `selectors` сопоставляет физический терм реальному уровню независимо от его номера в ADF04.
2. `rate_coefficients.csv`: `id;model;alpha_cm3_s;beta;gamma_K;Tmin_K;Tmax_K;reference_T_K;source` и дополнительные столбцы происхождения. Для Arrhenius k=α(T/Tref)^β exp(−γ/T).
3. `cross_sections.csv`: `id;energy_eV;sigma_cm2;energy_frame;units;source`; требуется `energy_frame=centre_of_mass`, `units=cm2`.

Пример стехиометрии и селектора уже находится в He(2³S)+H записях. Для нового молекулярного продукта прежде нужен состав/масса и энергия в `data/components/`; неизвестная энергия не принимается равной нулю. Трёхчастичные **входные** реакции в 2.1 не поддержаны; их нельзя преобразовать в двухчастичные подстановкой произвольной фоновой плотности без отдельного оператора.

После добавления запускайте `data validate`, изучайте `data_gaps.csv` / `pair_coverage.csv` и проверяйте независимый предельный случай. Положительные населённости и сохранённый заряд не проверяют достоверность выбранного физического коэффициента.

## Дополнение версии 2.4: общий пример He–H–Li

Реакции He–Li не зашиты в Python. Чтобы добавить новый элемент X по тому же принципу:

1. Подготовьте `data/elements/X/atom.json` и реальные таблицы уровней, переходов и сечений по прежней инструкции. Включите X/X II в `atomic_data.species` и начальные концентрации. Нейтральный атом и ион имеют одну ядерную массу и общую энергетическую систему отсчёта.
2. Создайте папку пары `data/reactions/He--X`. Декларации/стехиометрия находятся в `reactions.json`, сечения — в `cross_sections.csv`, коэффициенты — в `rate_coefficients.csv`. Форматы-примеры: `templates/pair_reactions.json`, `templates/pair_cross_sections.csv`, `templates/tabulated_rates.csv`.
3. В `selectors` привязывайте физический уровень через element, charge, n, multiplicity, L. Это устойчивее, чем фиксированный порядковый номер из ADAS. Для тонкой структуры, смешанных конфигураций и совпадающих квантовых чисел нужны однозначные идентификаторы; нельзя молча выбирать один из нескольких уровней.
4. У σ(E) нужны `energy_frame=centre_of_mass`, `units=cm2`, возрастающие энергии, неотрицательные значения, источник и область применимости. Для лабораторной энергии неподвижной мишени сначала выполните E_CM=E_lab*m_target/(m_projectile+m_target). Нельзя забывать пересчёт кэВ→эВ и м²→см².
5. Для k(T) доступны `arrhenius` (α(T/Tref)^β exp(-γ/T)), `power_exponential_temperature` (α(T/Tref)^β exp(-T/γ)) и `tabulated_loglog`. В последнем случае каждая строка — один узел: `reference_T_K` содержит T узла, `alpha_cm3_s` — k узла; Tmin/Tmax — общий диапазон. Минимум два положительных узла. За диапазоном продолжения нет.
6. У каждой реакции задайте `coefficient_convention`. Для σ(E) — `unordered_cross_section`; одинаковые реагенты получают фактор 1/2. У опубликованного k важно уточнить, определяет ли он число событий или число потерянных частиц. Пример He*+He* потребляет два метастабиля за одно событие.
7. Суммы числа ядер каждого элемента и заряда проверяются автоматически. Энергетический дефект рассчитывается из состояний, а не задаётся произвольной температурной поправкой. Если имеется отдельный химический носитель, опишите его состав и энергию в `data/components`.
8. Две альтернативные оценки одной реакции нужно пометить `alternative_group`/`alternative` и выбрать через `chemistry.datasets`, как у He*–H. Они не должны суммироваться как независимые процессы. Радиационная и нерадиационная перезарядка — разные каналы: для первой поддерживается `radiative=true` и энергетический фотонный вклад.
9. `thermal_inverse=true` допустим для обратной эндотермической **нерадиационной** реакции с известным прямым k(T). Он использует статистические веса и энергетический дефект текущих уровней. Это не способ восстановить σ(E) для немаксвелловского пучка. Для разных приведённых масс общий обратный оператор нужно отдельно обосновать; реализованные атомные перезарядки сохраняют массы пары.
10. Любую модельную замену обозначьте `estimated:true`, подробно заполните `model_note` и отдельно включите `allow_estimated_rates`. Только после научной проверки выставляйте `reviewed:true`; до этого храните кандидат в `templates`/`cache`, а не в рабочей папке `data/reactions`.
11. Выполните `python run.py --config configs/ВАША_СМЕСЬ.json --check`, затем короткий расчёт. Проверьте `reaction_catalogue.csv`, `chemical_reactions.csv`, `pair_coverage.csv`, `chemical_known_omissions.csv`, `chemical_domain_audit.csv`, `data_gaps.csv`, `quality.json` и балансы. Добавьте независимый проверочный предел: аналитическую бимолекулярную кинетику, опубликованный k(T), обратный баланс или измерение.

Численный оператор поддерживает две входящие частицы и две/три выходящие частицы. Реакции тройного столкновения, 2→1 радиационная ассоциация с отдельной молекулярной кинетикой и оператор состояния-разрешённых v,J требуют дополнительного физического модуля. Положительный баланс автоматически не дополняет неизвестную сеть.

Положение нового ионного/нейтрального источника задаётся без изменения ядра через `spatial_sources`; подробности в `SLAB_SOURCES_RU.md`. Подробный аудит того, что действительно подключено для He–H–Li: `PROCESS_AUDIT_2_4_RU.md`.
